# Split driver

The split driver creates two backends using the specified driver. One backend is used for write operations (create/update/delete/compact), the other is used for read operations (get/list/liststream/count/watch/dbsize/currentrevision).

This is NOT to be used for actual workloads, and must be enabled at build time with the `kine_split_driver` tag. The driver exists to allow testing the behavior of multiple Kine instances running against the same backend datastore, without having to run multiple kine processes. Some drivers may not function correctly or at all when wrapped by this driver.

## Endpoint Format

```
split://authority/path?query&driver=driver-name
```

The target endpoint string is generated by replacing the `split` schema name with the value of the `driver` query parameter, and opening the driver as usual. The `driver` query parameter must be the last parameter, and it must be prefixed with the `&` parameter separator.

For example, specifying an endpoint of `split://username:password@tcp(hostname:3306)/database-name?&driver=mysql` would create two backends using the endpoint `mysql://username:password@tcp(hostname:3306)/database-name?`. To test sqlite, you could use `split://&driver=sqlite`.
